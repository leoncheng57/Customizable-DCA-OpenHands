| 17 | 2026-08-20 | Agent skills are toggled **globally only** — one set of checkboxes on the Tools page patching the agent-server's default profile (`agent_context.disabled_skills` deny-list + the per-install `enabled` flag), applying to new conversations. No per-conversation override; `POST /conversations` is untouched | The upstream API cannot mutate a running conversation's `agent_context`: `PATCH /api/conversations/{id}` is title/tags only, `switch_profile` swaps the LLM, and `agent-profiles/{id}/activate` is a creation-time-only pointer — so a per-conversation toggle would be a confusing half-feature that silently fails to apply. Mirrors decision #11 (condenser is likewise a global default-profile setting). Effective state is the merge of BOTH upstream mechanisms (install-level `enabled` AND not deny-listed); the deny-list is the authority because it also covers auto-loaded user/public/project skills that were never explicitly installed, and the install-level flag is kept in lockstep so the upstream Canvas UI never disagrees. `agent_settings_diff` replaces lists wholesale, so `disabled_skills` is strictly read-modify-write. Listing takes THREE upstream reads, because `GET /api/skills/installed` only knows about explicitly installed skills: an auto-loaded public/user skill would have no row, and a skill with no row cannot be denied — so `POST /api/skills` (the merged effective set) is folded in and the list is `installed ∪ auto-loaded ∪ already-denied`. That probe is skipped when every source is off and is best-effort otherwise (a public load git-pulls the extensions repo), with `loadedUnavailable` distinguishing "could not look" from "there are none". Project skills resolve lazily per conversation from a workspace path that does not exist at global scope, so they stay togglable but unlistable. Every `agent_context` write also clears `skills: []`: upstream resolves `load_user`/`load_public` at model-construction time and PERSISTS every materialized skill (body text included) into `agent_context.skills` — measured live, flipping `load_public_skills` on inlined 59 skills, and turning it back off left 58 behind as now-explicit skills, making the source toggle one-way. The flags stay the source of truth and the materialized copy is wiped on every write. The three `load_*_skills` source flags ship as toggles too: they default to `false`, and a toggle whose source is off is a silent no-op — the UI must say "skill loading is off" rather than "nothing installed" |
